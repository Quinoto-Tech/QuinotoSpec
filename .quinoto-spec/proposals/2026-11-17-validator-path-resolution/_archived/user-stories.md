# User Stories (Validator Path Resolution)

**Proposal ID:** 2026-11-17-validator-path-resolution
**Prefijo:** VPAT-k4m7
**Estado:** proposed

| ID | User Story | Criterios de Aceptación | Prioridad | Estimación | Servicio |
|---|---|---|---|---|---|
| US-VPAT-k4m7-001 | Como **desarrollador/mantenedor del paquete**, quiero **una suite de regresión (`tests/test-installed-paths.sh`) que falle con la versión actual (RED)**, para **probar que el problema de rutas existe y que el fix no romperá nada al implementarlo**. | - [ ] El suite se ejecuta contra una instalación en directorio temporal (patrón `QUINOTOSPEC_INSTALL_TEST_MODE` / staging hermano)<br>- [ ] Con el código actual, el test falla verificando que los `.md` instalados contienen `agent-dist/` (RED observado y registrado en evidencia)<br>- [ ] El suite valida además el fallback de `resolve_package_root()` con un proyecto fixture sin `agent-dist/`<br>- [ ] El suite corre en Linux y macOS (portabilidad: `$TMPDIR`, sin dependencias GNU-only) | P1 | M | payload-python |
| US-VPAT-k4m7-002 | Como **agente de IA trabajando en un proyecto instalado**, quiero **que los `.md` del payload (workflows, SKILL.md, rules, bootstrap, templates, agents) referencien rutas ejecutables del destino de instalación**, para **poder correr el preflight y todos los validadores sin pasos manuales ni symlinks**. | - [ ] `install.sh` normaliza `agent-dist/` → ruta absoluta del config dir en los `.md` staged de `workflows/commands`, `skills`, `rules`, `bootstrap`, `templates`, `agents`, `config`<br>- [ ] Tras instalar global en OpenCode, `grep -rn "agent-dist" ~/.config/opencode/bootstrap/quinotospec-bootstrap.md` → 0 matches<br>- [ ] El comando de preflight del bootstrap instalado existe en disco y `contract.py validate --root . --strict` corre exit 0 en un proyecto fixture<br>- [ ] El rewrite es idempotente (re-ejecución = no-op sin errores)<br>- [ ] Rutas de instalación con espacios y `&` no corrompen el contenido reescrito | P1 | M | installer |
| US-VPAT-k4m7-003 | Como **instalador transaccional (sistema)**, quiero **normalizar las rutas ANTES de calcular el ownership manifest y mover el candidate a destino**, para **que el manifest refleje el contenido final instalado y el uninstall siga siendo coherente por SHA-256**. | - [ ] El orden de fases en `install.sh` es: staging → normalización → SHA-256 del manifest → verify → mv a destino<br>- [ ] Tras instalar y desinstalar, el manifest verifica los archivos `.md` reescritos sin conflictos y no deja residuos<br>- [ ] El rewrite NO modifica `*.py`, `*.sh`, `*.js`, `*.json` (verificación byte a byte contra el source en el suite)<br>- [ ] `verify_installation` pasa con los archivos normalizados | P1 | M | installer |
| US-VPAT-k4m7-004 | Como **agente de IA trabajando en un proyecto instalado**, quiero **que `update_agents.py` y `template_resolver.py` resuelvan workflows/rules/templates/skills desde la raíz de instalación del propio script cuando `root/agent-dist` no exista**, para **poder regenerar `AGENTS.md` y resolver templates desde cualquier proyecto sin `agent-dist/`**. | - [ ] Helper `resolve_package_root(user_root)`: devuelve `user_root/agent-dist` si existe; si no, `Path(__file__).resolve().parents[2]` (convención de `quinotospec_common.py`)<br>- [ ] Desde un proyecto fixture (sin `agent-dist/`), `update_agents.py --root .` genera `AGENTS.md` leyendo workflows/rules/templates del destino de instalación<br>- [ ] Desde el repo fuente, el comportamiento es byte-idéntico al actual (regresión cero)<br>- [ ] El significado de `--root` no cambia: config/artefactos del usuario se leen del root del proyecto | P1 | M | payload-python |
| US-VPAT-k4m7-005 | Como **CI y mantenedor del paquete**, quiero **una aserción de invariant en `smoke-release.sh` y los gates completos en verde**, para **garantizar que ningún release reintroduzca referencias `agent-dist/` rotas en el payload instalado**. | - [ ] `smoke-release.sh` instala el tarball en un temp dir y verifica: 0 ocurrencias de `agent-dist/` en `.md` instalados + preflight del bootstrap ejecutable con exit 0<br>- [ ] Auditoría de los ~108 archivos fuente: ninguna exclusión necesaria, o exclusiones documentadas en el suite<br>- [ ] `bash scripts/validate-all.sh --strict` → 0 errores, 0 warnings<br>- [ ] `bash tests/run-all-tests.sh` → 29/29 suites verdes (28 existentes + la nueva)<br>- [ ] Evidencia del ciclo RED→GREEN registrada en `.quinoto-spec/evidence/TSK-VPAT-k4m7-*/` y validada con `evidence_validate.py` | P1 | M | installer |
